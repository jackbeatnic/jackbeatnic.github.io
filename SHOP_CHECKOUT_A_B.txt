WARIANTY B — JAK JEST TERAZ
---------------------------
  Front: Connect → Buy → eth_sendTransaction
    to    = pay_address studia (0xf0b8…)
    value = okrągły pay_amount (np. 1.797 AVAX), NIE 1.797001
    data  = 0x474a4231 || uint256 tokenId     (ASCII "GJB1")

  Kasa (vps/worker/evm_watch.py, systemd kasa-evm):
    1. tx.to == studio
    2. parse data → token_id
    3. exact wei AND token_id w shop_pay_wei.json v2
    4. EVM_LIVE=1 → safeTransferFrom(studio, payer, id, 1)  z klucza na VPS
    5. brak data / inna kwota → status=tip, bez NFT

  Cennik: listing/sale_index.csv → build_sale_index.py
          → www/data/sale_index.json
          → www/data/shop_pay_wei.json (version 2)

  Zmiana ceny = edycja CSV (price + pay_amount, okrągłe) → build → push Pages
  + rsync shop_pay_wei.json na VPS. Kasa czyta JSON co pętlę, bez restartu.
  ends_at chowa kartę po dacie. Cron „po 30 dniach wróć”: drugi CSV + ten sam
  build/push (deploy key na kasie). Nie Seaport, nie mikro-AVAX.

  Ścięcie starych mikro-kwot (gdyby znów weszły):
    python3 listing/build_ns_avax_shop.py --round-csv

  Test: python3 vps/worker/test_shop_buy.py

  Wdrożenie: NAJPIERW git pull + restart kasa-evm na VPS,
             DOPIERO POTEM push Pages. Inaczej kasa nie widzi GJB1
             i kursor bloków i tak idzie do przodu.

  Ręczny przelew / QR = napiwek (nie ma tokenu w data).
